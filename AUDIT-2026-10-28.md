# rl-crypto — project audit (2026-10-28)

Status: **archived**. This document records why the project was stopped and what
would be worth carrying into a restart. No code was changed by this audit; the
only accompanying actions were pushing the local-only research branches to
`origin` as a backup and tagging the archive points.

## Method

- Every opencode session whose working directory was this repo: **54 sessions**,
  2026-10-10 → 2026-10-28, **$5.47**, 30.0M input / 1.8M output tokens, 4,537
  `bash` calls.
- Session claims were re-checked against the repo, the experiment ledger, the
  run artifacts under `~/.local/share/rl-crypto/model-improve/runs/`, and the
  harness source on `honest-gate/2026-10-25`.

## Verdict

Three pipelines are conflated in this repo and they failed for different
reasons:

1. **Production data pipeline — healthy.** 15 tickers, 30-minute `live` /
   2-hour `train`, matrix jobs plus a single writer, watchdog recovery, a
   generated dashboard. 320 commits, no missed schedule observed.
2. **Measurement harness — genuinely good, and it worked.** Pre-registration,
   protected-file pin, frozen holdout timestamp, canaries, MDE/power gate,
   `inconclusive` as a real outcome, "negative is success". It correctly
   concluded there is **no directional edge**.
3. **Agentic improvement loop — the actual failure.** ~11,700 lines of
   orchestration, 6 roles and 9 steps to run one canary, which then consumed
   2.66M tokens (ceiling 2.0M) and produced no evaluation. None of it was ever
   merged to `main`.

The project did not fail at science. It failed at **shipping the apparatus** and
at **data scale**.

## The scientific result

From the committed archive and the `honest-gate` ledger:

| target | beats baseline | reading |
|---|---|---|
| `fwd_return` | 0/15 | no directional skill |
| `fwd_direction` | 0/15 | no directional skill |
| `fwd_volatility` | 9/15 (5/15 under strong baselines) | modest, real |
| `fwd_volume_ratio` | 15/15 | solid, not tradable alone |

- Dataset: **27,235 bars / 15 tickers ≈ 1,816 each ≈ 75 days of hourly,
  price-only data**. News is live-only, so news features are constant in
  training and are dropped by design.
- H1 (pooled panel) is recorded **negative**; H2 is blocked on upstream history
  limits (Coinbase empty, Kraken ~30 d, Binance needs pagination); H3–H9 are
  already `deferred-underpowered`.
- The ledger holds 25 entries, 6 pre-registrations and 3 verdicts, all
  diagnostic/negative. No verdict was ever promoted.

Conclusion: the measurement is honest and the data cannot support a directional
claim. More model classes will not change that.

## Findings

### 1. The harness was never on `main`, but the docs said it was (critical)

`main` contains none of `tools/model_improve.py`, `tools/model_lab.py`,
`experiments/`, or `.opencode/{agents,command,skills,tools}`. `README.md:237`
still documents `tools/model_improve.py`, and `README.md:97` lists tooling that
is not present. CI on `main` ran 191 tests; the harness's 398 tests never ran on
`main`.

Consequence: `/model-improve-auto` in the primary checkout pointed at a missing
file, and the 2026-10-27 session spent its first ~15 tool calls rediscovering
that.

### 2. Two truths, no sync (high)

At audit time `honest-gate/2026-10-25` was 56 commits ahead and 41 behind
`main`, and the primary checkout had been left on a feature branch for ~3 days
while production kept committing. Unlike `nixos-config`, this clone has no
auto-fetch/pull, so a live pipeline looked dead.

### 3. Orchestration was over-built relative to the work (high)

6,208 lines in the orchestrator, 3,464 in the lab, 2,020 in
`experiments.py` — 11,692 lines to produce 3 verdicts in 4 days. Six role
agents, nine skills, a nine-step run, four non-blocked outcomes, an authority
model, and a reviewer that mutates its own agent prompts. `v-verifier` used 876
tool calls for a read-only check; `t1-split-mme` used 536.

### 4. The budget model could not fit the session overhead (high)

`maxTokensPerRun=2,000,000`, while per-step overhead was 66k–100k tokens
because every role inherited the global MCP toolset. A canary needs ~90 steps.
The lead spent ~15 steps reading `model_improve.py` / `experiments.py` — code it
is forbidden to change — and the run was blocked at 2,664,760 tokens with no
evaluation. The guard behaved correctly: it blocked rather than inventing a
result.

### 5. Self-mutation had no commit boundary (high)

The post-run reviewer edited `.opencode/agents/model-improve-lead.md` and left
it uncommitted; the worktree ended dirty, which then makes `team_cleanup`
refuse.

### 6. Cleanup had no owner (high)

Fourteen worktrees were removed manually (~2.9 GB reclaimed). There are two
worktree creators (`model_improve` and `team_spawn`), each cleaning up only on a
clean exit; `team_cleanup` blocks on dirty state and only knows the current
team, so abandoned worktrees become unowned.

### 7. Bookkeeping under-reported what ran (medium)

`roles.json` records only the top-level lead; the researcher actually ran and
wrote artifacts. `SCOREBOARD.md` rendered a stale protected hash versus the
gate. Run artifacts live outside the repo under
`~/.local/share/rl-crypto/model-improve/` and are gitignored, so they are not
durable.

### 8. Nine overlapping entry points (medium)

`rl-crypto`, `rl-pipeline`, `/model-improve`, `/model-improve-auto`,
`/rl-model-lab`, the `rl-model-lab` tool, `model_improve.py`, `model_lab.py`,
and the `model-improvement` skill. Nothing told a newcomer which to use.

### 9. No agent guidance file (medium)

No `AGENTS.md` or `ARCHITECTURE.md` exists anywhere in the history. Every
session re-derived the layout; the status session spent ~35 tool calls mapping
it.

### 10. The data ceiling is the real ceiling (critical for a restart)

75 days of hourly, price-only data; no news history; no funding, open interest
or order-book data. H2 is blocked upstream and H3–H9 are already
underpowered-only. Any restart must decide the go/no-go before writing model
code: obtain multi-year history + news history + derivatives, or accept this as
an activity/volatility project rather than a trading one.

## What to keep

1. The honesty machinery: pre-registration, protected-file pin, frozen holdout
   timestamp, canaries, MDE/power gate, `inconclusive`, "negative is success".
2. The production pipeline: 30-minute live / 2-hour train, matrix + single
   writer, watchdog, generated dashboard.
3. The data contract: union join, `has_price`/`has_news`, `None` never
   fabricated as `0`.
4. The 398-test suite, once it lives on the default branch.

## What to drop in a restart

The six-role ensemble for a canary, the self-mutating reviewer, the `auto`
executor ambiguity, worktree-per-teammate as the default, and the 6.2k-line
orchestrator.
